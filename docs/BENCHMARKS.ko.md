# RH Lingo 벤치마크 (v1.0.0-beta.3)

🇺🇸 English: [BENCHMARKS.md](BENCHMARKS.md)

1·2·4번은 beta.2(한가한 PC)에서, 3·5번은 beta.3 엔진에서 쟀어요. 다시 돌릴 수 있는 스크립트 [`tools/bench.py`](../tools/bench.py)로 쟀어요. (원본 수치: [`bench_results.json`](bench_results.json))

## 숫자를 읽기 전에

- **PC 한 대, 한 번 측정.** AMD Ryzen 7 9800X3D (8코어/16스레드), RAM 64 GB, Windows 11, CPU만 사용(GPU 안 씀). 측정 중에도 평소 쓰는 프로그램들이 켜져 있었어요. 사양이 낮은 PC는 더 느려요. 코어가 적은 PC에서는 앱이 알아서 더 작은 음성 모델을 고르는데, 그 경우는 여기서 재지 않았어요.
- **합성 음성이에요.** Windows 기본 음성(한국어 "Heami", 영어 "Zira")에 시드를 고정한 소음을 섞어서, 다시 돌려도 똑같이 나와요. 실제 사람 목소리와 마이크는 달라요. 숫자는 '설정끼리 비교'와 '대략적인 규모'를 보는 용도지, 약속이 아니에요.
- **일본어 음성 인식은 못 쟀어요**: Windows에 일본어 음성이 기본으로 없어서요. 일본어는 번역 테스트에만 들어 있어요.
- 음성 모델은 `small`(8코어 이상 기본값), 번역은 오프라인 M2M100 "표준"(418M, int8)이에요.

## 1. 가벼움

| 항목 | 결과 |
|---|---|
| 설치 파일 | 66.6 MB |
| 설치 크기 (앱만, 모델 제외) | 251 MB |
| exe 실행 → 창이 뜨기까지 | 0.7초 |
| 앱 대기 중 메모리 | 약 70 MB |
| 앱 대기 중 CPU | 코어 1개의 0.8% |
| 듣는 중(무음) CPU | 코어 1개의 0.16% |
| 음성 모델 `small` | 다운로드 464 MB · 로드 1.8초(이미 읽은 적 있을 때) · RAM +307 MB |
| 오프라인 번역 모델 | 다운로드 494 MB · 로드 0.5초 · RAM +513 MB |

음성 모델과 번역 모델은 허락하신 뒤에만 받고, 번역 모델이 없어도 앱은 동작해요(받아쓰기만, 또는 직접 켠 온라인 서비스).

## 2. 속도 (끝에서 끝까지 지연)

**말이 끝난 순간부터 글자가 나올 때까지**의 시간이에요(각 24문장, 실시간 속도로 입력). 말이 끝났는지 확인하려고 기다리는 무음 0.4초가 포함돼 있어요.

| 조건 | 중앙값 | p90 | 최대 |
|---|---|---|---|
| 말 → 글자, 한가한 PC | 0.53초 | 0.60초 | 0.61초 |
| 말 → 번역된 글자 (한→일, 오프라인), 한가한 PC | 0.74초 | 0.81초 | 0.87초 |
| 말 → 글자, CPU를 잡아먹는 프로세스 8개가 도는 중 | 0.57초 | 0.66초 | 0.70초 |

세부: 3~4초짜리 문장의 음성 인식만 약 0.17~0.20초, 문장 하나의 오프라인 번역은 약 0.18~0.21초예요(한→일은 p90이 0.47초까지).

## 3. 음성 인식 정확도 (`small`, beta.3 엔진)

전체 과정(감지 → 인식)의 글자 오류율(CER, 낮을수록 좋음). 한국어 8문장 + 영어 8문장, 소음 시드 2개. "인식됨"은 앱이 말을 잡아낸 비율이에요.

| 조건 | CER 한국어 | CER 영어 | CER 전체 | 인식됨 |
|---|---|---|---|---|
| 깨끗함 | 3.2% | 0.5% | 1.9% | 100% |
| 선풍기, SNR 10 dB | 13.1% | 1.0% | 7.0% | 100% |
| 전원 웅웅 소리, SNR 5 dB | 2.6% | 0.5% | 1.5% | 100% |
| 키보드 소리, SNR 3 dB | 14.8% | 25.5% | 20.2% | 81% |
| 주변 말소리, SNR 8 dB | 9.1% | 3.2% | 6.1% | 100% |
| 아주 작은 목소리 (볼륨 10%) | – | – | – | **0%** |

beta.3에서 달라진 점(같은 말뭉치, small 모델): 탐색 폭을 넓혀서(beam 5) 주변 말소리에서의 오류율이 25% → 10%로 줄었어요. 아주 짧은 소리도 받아서(0.35초 → 0.15초, 한 단어짜리에는 호출어 힌트) "야", "네", "Hey" 같은 짧은 호출의 인식이 27번 중 11번 → 27번이 됐고, 선풍기·웅웅 소리·키보드·무음에서 잘못 반응하지 않았어요.

솔직하게 적는 약점이에요:
- 기본 민감도(40)에서는 **아주 작은 목소리를 못 잡아요**. 설정 → 마이크 → "자동 맞춤"을 누르면 내 마이크에 맞게 고쳐져요.
- **키보드 소리**가 크면 오류율이 올라가고 발화의 19%를 놓쳐요. 소프트웨어 필터보다 입 가까이 두는 마이크가 훨씬 도움이 돼요. 기본 잡음 제거는 오히려 정확도를 낮춘다는 시험 결과 때문에 꺼 둔 상태예요.

## 4. 번역 품질 (오프라인 "표준")

chrF 점수(0~100, 높을수록 좋음. 직접 쓴 정답과 글자 n-gram이 얼마나 겹치는지)이고, 방향마다 대응 문장 8개로 쟀어요. 정답이 한 가지뿐이라 잘 의역한 번역도 낮게 나와요. 뜻이 맞아도 절대값이 낮아 보이니, 방향끼리 비교하는 참고용으로 보세요.

| 방향 | chrF |
|---|---|
| 일본어 → 영어 | 41.3 |
| 영어 → 일본어 | 38.3 |
| 한국어 → 일본어 | 37.5 |
| 한국어 → 영어 | 37.2 |
| 일본어 → 한국어 | 23.6 |
| 영어 → 한국어 | 22.5 |

예시 (한국어 → 영어): "안녕하세요, 오늘 처음 왔는데 월드가 정말 예뻐요." → "Hello, I came here for the first time today and world is really nice."

한국어로 옮길 때 오프라인 모델이 가장 약해요(딱딱한 말투, 조사 누락). 내 키로 쓰는 DeepL이나 Gemini가 더 잘 옮기고, 설정에서 "고품질" 오프라인 모델(1.2 GB)도 고를 수 있어요(여기서는 재지 않았어요).

## 다시 재기

```bash

```

## 5. 어떤 모델이 좋을까? (가성비 비교)

모든 모델을 같은 말뭉치·같은 소음 조건에서 쟀어요(beta.3 엔진, CPU만 사용). CER은 위 다섯 가지 들리는 조건(깨끗함·선풍기·웅웅 소리·키보드·주변 말소리)의 평균이에요. "인식 단계"는 3~4초 문장을 Whisper가 처리하는 시간인데, **VRChat과 Unity가 켜져 있는 상태에서** 쟀기 때문에 한가한 PC(small은 약 190 ms)보다 느리게 나와요. 모델끼리 비교하는 용도로만 보세요.

| 음성 모델 | 다운로드 | CER(평균) | 깨끗함 | 선풍기 | 키보드 | 주변 말소리 | 인식 단계 |
|---|---|---|---|---|---|---|---|
| tiny | 75 MB | 23.5% | 7.8% | 28.1% | 33.7% | 33.0% | 90 ms |
| base | 145 MB | 16.8% | 8.0% | 19.1% | 30.5% | 21.3% | 138 ms |
| **small** | 480 MB | **10.0%** | 1.2% | 14.6% | 26.8% | 7.1% | 439 ms |
| medium | 1.5 GB | 7.1% | 0.2% | 3.6% | 25.2% | 6.4% | 1178 ms |
| large-v3-turbo | 1.6 GB | 9.5% | 3.8% | 8.1% | 27.1% | 5.6% | 1098 ms |

- **small이 가성비 최고예요**: base는 6.8%p 나쁘고, medium은 2.9%p만 더 좋은데 다운로드는 3배, 속도는 약 2.7배 느려요. large-v3-turbo는 CPU에서는 small보다 낫지 않아요.
- **base**는 저사양 PC(4~7코어)용 대안이고, **tiny**는 너무 부정확해서 추천하지 않아요. **medium / large-v3-turbo**는 GPU가 있을 때만 의미가 있어요.
- 앱의 *auto* 설정도 이 결과를 따라요: 8코어 이상은 small, 4코어 이상은 base, 그 외는 tiny.

| 오프라인 번역 모델 | 다운로드 | RAM | chrF(6방향 평균) | 한→영 | 일→한 | 한→일 | 문장 하나(바쁜 PC) |
|---|---|---|---|---|---|---|---|
| **표준** (M2M100 418M) | 494 MB | +513 MB | 33.4 | 37.2 | 23.6 | 37.5 | 0.49초 |
| 고품질 (M2M100 1.2B) | 1.25 GB | +1236 MB | 36.6 | 44.2 | 38.2 | 30.5 | 0.81초 |

- **표준이 더 좋은 기본값이에요**: 고품질은 평균 +3.2 chrF 좋아지지만 메모리를 2.5배 쓰고 더 느리며, 한국어 → 일본어는 오히려 나빠요. 일본어 → 한국어(+14.6)와 한국어 → 영어(+7.0)에서 주로 도움이 돼요.

## 6. GPU (NVIDIA RTX 5080, 선택형 가속 팩)

5번과 같은 말뭉치·조건에서, 선택형 가속 팩(cuBLAS 12.9 + cuDNN 9.27, 다운로드 1.24 GB)을 쓰고 음성 모델을 GPU(float16)로 돌렸어요. VRChat이 켜져 있는 상태에서 쟀어요.

| 음성 모델 | 장치 | 인식 단계 | CER(평균) | 깨끗함 | 선풍기 | 키보드 | 주변 말소리 |
|---|---|---|---|---|---|---|---|
| small | CPU | 439 ms | 10.0% | 1.2% | 14.6% | 26.8% | 7.1% |
| small | **GPU** | 85 ms | 9.3% | 0.9% | 12.2% | 27.1% | 5.2% |
| large-v3-turbo | CPU | 1098 ms | 9.5% | 3.8% | 8.1% | 27.1% | 5.6% |
| large-v3-turbo | **GPU** | **59 ms** | **8.0%** | 0.2% | 8.5% | 27.6% | 2.9% |

- NVIDIA GPU가 있으면 **GPU에서 large-v3-turbo가 최선이에요**: 같은 모델을 CPU로 돌릴 때보다 약 18배 빠르고, 측정한 것 중에서는 CPU의 medium(7.1%, 하지만 약 20배 느림)을 빼면 가장 정확해요.
- GPU가 없으면 small이 계속 가성비 최고예요.
